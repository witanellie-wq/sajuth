# HANAHAYAN · 직원 근태 · 업무태도 · 급여 관리

localStorage 로 저장하던 `staff-attitude-log_v6.html` 을 **Supabase 저장 + 실시간 동기화** 로 바꾼 버전입니다.
카운터 태블릿 · 폰 · PC 어디서 열어도 같은 데이터가 보이고, 한쪽에서 저장하면 다른 화면이 자동으로 갱신됩니다.

빌드 도구 없이 **정적 HTML + Supabase JS SDK (CDN)** 만 씁니다.

```
staff-attitude/
├── index.html                    앱 전체 (UI · 로직 · 스타일)
├── config.js                     Supabase 주소 / anon key / 계정 이메일  ← 여기만 채우면 됩니다
├── schema.sql                    테이블 · RLS · Realtime (최초 1회)
├── patch-01-restrict-access.sql  접근을 지정한 2개 계정으로 제한
├── patch-02-expenses.sql         지출 관리 (고정비 · 소모품) 테이블 추가
├── patch-03-business.sql         지출을 사업장별(하나하얀 / 위튼)로 분리
├── patch-04-targets.sql          매출 목표 기록 테이블 추가
├── vercel.json                   배포 설정 (보안 헤더)
└── .vercelignore
```

> SQL 파일은 **번호 순서대로** 한 번씩 실행하면 됩니다. 여러 번 실행해도 안전합니다.
> 처음부터 새로 세팅한다면 `schema.sql` → `patch-01` → `patch-02` → `patch-03` → `patch-04` 순서입니다.

## 설치 — 4단계

### 1단계 · 테이블 만들기

1. Supabase Dashboard → 예약 사이트와 **같은 프로젝트** 선택
2. 왼쪽 **SQL Editor** → **New query**
3. `schema.sql` 전체를 복사해 붙여넣기
4. 붙여넣은 내용 맨 위 `staff_is_admin()` 안의 이메일이
   `admin@hanahayan.co.th` 로 되어 있는지 확인 (다른 걸 쓰려면 여기서 바꾸세요)
5. **Run** ▶

기존 예약 테이블은 건드리지 않습니다. 새로 만드는 건 `staff_` 로 시작하는 6개뿐입니다.
여러 번 실행해도 안전합니다.

### 2단계 · 비밀번호 계정 2개 만들기

비밀번호 게이트는 Supabase Auth 로 진짜 로그인을 합니다.
그래서 **비밀번호를 모르면 anon key 를 알아도 데이터를 한 줄도 못 읽습니다.**

Dashboard → **Authentication** → **Users** → **Add user** → **Create new user**

| 이메일 | 비밀번호 | 용도 |
|---|---|---|
| `staff@hanahayan.co.th` | 직원 공용 비밀번호 | 근태 입력 · 근태표 · 평가서 |
| `admin@hanahayan.co.th` | 관리자 비밀번호 | 위 + 급여 · 커미션 · 경고 · 고용조건 |

> ⚠ 두 계정 모두 **Auto Confirm User** 를 체크하세요.
> (또는 Authentication → Providers → Email 에서 "Confirm email" 을 끄세요)

### 3단계 · config.js 채우기

Dashboard → **Project Settings** → **API** 에서 두 값을 복사합니다.

```js
window.STAFF_CFG = {
  url:        'https://xxxxxxxxxxxx.supabase.co',   // Project URL
  anonKey:    'eyJhbGciOi...',                      // anon / public key
  staffEmail: 'staff@hanahayan.co.th',
  adminEmail: 'admin@hanahayan.co.th'               // schema.sql 과 반드시 동일
};
```

anon key 는 공개되어도 괜찮습니다 — RLS 가 로그인하지 않은 접근을 전부 막습니다.

### 4단계 · Vercel 배포

```bash
cd staff-attitude
npx vercel login          # 브라우저로 로그인
npx vercel --prod         # 배포
```

처음 실행하면 몇 가지를 물어봅니다:

- `Set up and deploy?` → **Y**
- `Which scope?` → 본인 계정
- `Link to existing project?` → **N** (새 프로젝트)
- `What's your project name?` → 예: `hanahayan-staff`
- `In which directory is your code located?` → **`./`** (그대로 Enter)
- `Want to modify these settings?` → **N** (빌드 없음, 정적 파일 그대로)

끝나면 `https://hanahayan-staff.vercel.app` 같은 주소가 나옵니다.
이 주소를 태블릿 · 폰 홈 화면에 추가해 두면 앱처럼 씁니다.

> 나중에 내용을 고친 뒤에는 `npx vercel --prod` 만 다시 실행하면 됩니다.

## 기존 데이터 이전 (localStorage → Supabase)

**예전 파일과 새 사이트를 둘 다 열어 둔 채로** 진행하세요.

### ① 예전 파일에서 백업 내보내기

1. 기존에 쓰던 `staff-attitude-log_v6.html` 을 **평소 쓰던 그 브라우저 · 그 기기**에서 엽니다
   (데이터가 그 브라우저 안에만 있으므로 반드시 원래 기기여야 합니다)
2. 오른쪽 위 **📋 텍스트 백업 / 복원** 클릭
3. **파일로 저장 (.json)** 클릭 → `attendance_backup_….json` 이 다운로드됩니다
4. 아래 숫자(직원 N명 · 기록 N건)를 메모해 두세요 — 나중에 대조합니다

> 여러 기기에 나눠 저장돼 있었다면, **기기마다 위 과정을 반복해 파일을 여러 개** 만드세요.
> 3단계에서 하나씩 순서대로 가져오면 됩니다 (중복은 자동으로 걸러집니다).

### ② 새 사이트에 관리자로 로그인

1. 배포된 주소를 엽니다
2. 게이트에 **관리자 비밀번호**를 입력합니다
   (가져오기는 급여 · 경고까지 건드리므로 관리자만 가능합니다)

### ③ 가져오기

1. 오른쪽 위 **📋 백업 / 가져오기** 클릭
2. **파일 열기** → ①에서 받은 `.json` 선택
3. **가져오기 (합치기)** 클릭
4. 아래에 `✓ 기록 +N · 직원 +N` 이 뜨면 완료

파일이 여러 개면 2~3을 반복하세요.
**같은 파일을 실수로 두 번 눌러도 중복되지 않습니다** (내부적으로 원본 id 로 걸러냅니다).

> **합치기는 기록만 더합니다.** 백업에 있는 직원이 이미 서버에 있으면
> 그 직원의 **정기 휴무 · 인턴 기간 · 급여 설정은 덮어쓰지 않습니다.**
> 예전 설정을 그대로 쓰시려면 가져온 뒤 `직원 관리` 에서 확인하세요.
> 백업의 직원이 서버에 없으면 새로 만들어집니다.

### ④ 대조 확인

- **월 근태표** 탭에서 예전 달을 골라 칸이 그대로인지
- **급여 · 커미션** 탭에서 지급 체크와 금액이 맞는지
- **직원 관리 → 고용 조건** 에서 급여 방식 · 급여액이 맞는지
- 백업 모달 아래 숫자가 ①에서 메모한 숫자와 같은지

여기까지 맞으면 다른 기기(폰 · 태블릿)에서도 같은 주소를 열어 **직원 비밀번호**로 들어가
같은 데이터가 보이는지 확인하세요. 그러면 이전이 끝난 겁니다.

> ⚠️ **전체 덮어쓰기** 는 서버의 모든 데이터를 지우고 바꿉니다.
> 이전 작업에는 **가져오기(합치기)** 만 쓰세요. 덮어쓰기는 처음부터 다시 시작할 때만 씁니다.

## 지출 관리 (`지출` 탭 · 관리자 전용)

한 화면에서 **급여 + 고정비 + 소모품**을 합쳐 그 달 총지출을 봅니다.

맨 위 요약 카드는 5칸입니다:

| 급여 | 고정비 | **급여 + 고정비** | 소모품 · 기타 | 이달 총지출 |
|---|---|---|---|---|
| 급여·커미션 탭에서 자동 | 고정비 표 합계 | **매달 고정으로 나가는 돈** | 그 달 일시 지출 | 전부 합친 값 |

가운데 초록 카드(`급여 + 고정비`)가 **매달 반드시 나가는 고정 지출**입니다.
소모품처럼 달마다 들쭉날쭉한 돈을 빼고 보고 싶을 때 이 칸만 보면 됩니다.

### 매출 목표 — 이달 · 다음 달

`매출 목표` 표에 **사업장별로 이달 목표와 다음 달 목표**를 나란히 적습니다.
다음 달 목표를 미리 적어두면 달이 바뀔 때 자동으로 `이달 목표` 자리로 옮겨집니다.

표 아래에 **예상 이익**이 자동으로 계산됩니다:

```
목표 매출 ฿350,000 − 이달 총지출 ฿145,000 = 예상 이익 ฿205,000 · 이익률 59%
```

지출이 목표보다 크면 붉게 바뀌고 부족액을 보여줍니다.
(총지출 = 급여 + 고정비 + 소모품. 특정 사업장을 고르면 급여가 빠집니다.)

### 사업장 나눠 보기

고정비와 소모품 모두 **사업장**(하나하얀 / 위튼 타일랜드)을 지정합니다.
화면 위 `사업장` 선택으로 한쪽만 보거나, `전체 사업장`으로 두 곳을 합쳐 볼 수 있습니다.
전체일 때는 요약 카드 아래에 **사업장별 소계 표**가 함께 나옵니다.

- 사업장을 늘리려면 `index.html` 의 `const BIZ = [...]` 에 한 줄 추가하면 됩니다.
- 직원 급여는 사업장 구분이 없어서, 특정 사업장을 선택하면 급여 카드가 `—` 로 바뀌고
  총지출에 `급여 제외` 라고 표시됩니다. 급여도 사업장별로 나누고 싶으면 알려주세요.

### 분류는 직접 입력할 수 있습니다

`분류` 칸은 추천 목록에서 고르거나 **원하는 이름을 그대로 타이핑**해도 됩니다.
칸을 클릭하면 **값이 이미 들어 있어도 전체 목록이 열리고**, 현재 값에는 ✓ 표시가 붙습니다.
직접 쓴 분류는 `직접 만든 분류` 그룹으로 목록에 남아 다음부터 바로 고를 수 있습니다.
(추천 목록에 있는 분류만 태국어가 함께 표시되고, 직접 쓴 분류는 쓴 그대로 나옵니다.)

### 표 안의 모든 칸은 바로 고칠 수 있습니다

고정비와 지출 모두, 이미 입력한 항목을 **표에서 직접 수정**합니다. 고치는 즉시 저장됩니다.

- 고정비: 항목 · 사업장 · 분류 · 납부일 · **기본 금액** · 이달 금액 · 비고
- 지출: 날짜 · 사업장 · 분류 · 내용 · **비고** · 금액

`기본 금액` 과 `이달 금액` 은 다릅니다 — **기본 금액**을 고치면 앞으로 모든 달에 적용되고,
**이달 금액**은 그 달에만 적용됩니다(전기요금처럼 달마다 다를 때). 비워두면 기본 금액을 씁니다.

### 지급 처리

`지급 처리` 버튼을 누르면 지급 완료(초록)로 바뀌고 지급일이 오늘 날짜로 자동 입력됩니다.
다시 누르면 미지급으로 되돌아갑니다. 급여 탭도 같은 방식입니다.

### 고정비 — 한 번 등록해두면 매달 자동

임대료 · 전기 · 인터넷처럼 매달 나가는 돈은 **항목을 한 번만 등록**하면 됩니다.
그 뒤로는 매달 표에 자동으로 뜨고, **납부 체크만** 하면 됩니다.

- **이달 금액** 칸을 고치면 **그 달에만** 적용됩니다 — 전기요금처럼 달마다 다른 항목에 쓰세요.
  비워두면 기본 금액이 들어갑니다.
- **납부일**(매월 며칠)을 넣어두면, 날짜가 지났는데 미납이면 빨갛게 `미납` 표시가 붙습니다.
- 요약 카드 아래에 **이달 미납 고정비**가 항목명·금액과 함께 한 줄로 뜹니다.
- 계약이 끝난 항목은 **중지** — 다음 달부터 표에서 빠지고 지난 기록은 남습니다.
  **삭제**는 납부 이력까지 지웁니다 (되돌릴 수 없습니다).

### 소모품 · 기타 지출 — 한 번만 나가는 돈

소모품 구입, 장비 수리, 세금 납부처럼 일시적인 지출을 그때그때 적습니다.
**등록한 날짜가 속한 달**의 요약에 자동 합산되고, 분류별 소계가 막대로 표시됩니다.

분류: 소모품 / 제품·재고 / 장비·수리 / 마케팅 / 세금·수수료 / 기타

### 내보내기

`지출 CSV` 를 누르면 그 달의 **고정비 + 소모품 + 급여 합계**가 한 파일로 나옵니다.
`인쇄 / PDF` 로 그대로 출력할 수도 있습니다.

## 기록 색깔이 뜻하는 것

칸과 기록의 **색은 "출근 구분"과 "태도 점수" 중 나쁜 쪽**을 따릅니다.
정시 출근이어도 그날 태도 점수가 낮으면 노랑·빨강으로 바뀌기 때문에,
근태표를 훑는 것만으로 문제가 있었던 날이 바로 눈에 띕니다.

| 색 | 뜻 |
|---|---|
| 🟩 진초록 | **우수** — 근태 정상 + 태도 4.5 이상 |
| 🟩 연초록 | 보통 — 근태 정상 + 태도 3.5~4.4 |
| 🟨 노랑 | **주의** — 지각/사전통보 **또는** 태도 2.5~3.4 |
| 🟥 빨강 | **문제** — 무단 지각/결근 **또는** 태도 2.5 미만 |
| 🟪 보라 | 병가 |
| ⬜ 회색 | 휴무 |

칸 안의 기호(● △ ✕ ⊗ 병 휴)는 그대로 **출근 구분**을 뜻합니다.
즉 `●`(정상 출근)인데 빨간 칸이면 → **출근은 했지만 그날 문제가 있었던 날**입니다.

- 로그인은 브라우저에 유지됩니다. 매번 다시 칠 필요는 없습니다.

### 데이터베이스 차원의 보호 (RLS)

- 6개 테이블 모두 RLS **ON**. 로그인하지 않으면 anon key 만으로는 아무것도 못 읽습니다.
- `staff_payroll` · `staff_commissions` · `staff_warnings` 는
  JWT 이메일이 관리자와 일치할 때만 읽고 쓸 수 있습니다 — UI 를 우회해도 못 봅니다.

> **알아 두실 점 하나.** 요청하신 스키마대로 급여액(`wage`)이 `staff_members` 안에 있습니다.
> 이 테이블은 직원 계정도 읽어야 하므로(이름 · 출근시각 · 정기휴무), 화면에서는 고용 조건을
> 관리자 뒤로 가려 뒀지만 **DB 차원에서는 직원 비밀번호를 아는 사람이 급여액을 조회할 수 있습니다.**
> 완전히 막으려면 `wage` · `pay_type` 을 `staff_pay_terms` 같은 관리자 전용 테이블로 분리하면 됩니다.
> 필요하시면 말씀 주세요 — 30분이면 됩니다.

## 동작 방식 메모

- **저장 즉시 업로드.** 버튼을 누르는 순간 Supabase 로 갑니다. 별도 저장 버튼은 없습니다.
- **Realtime 구독.** 다른 기기의 변경은 0.4초 안에 화면에 반영됩니다.
  단, 입력 중인 칸이 있으면 그 칸에서 손을 뗄 때까지 화면을 다시 그리지 않습니다.
- **충돌은 last-write-wins.** 두 사람이 같은 칸을 동시에 고치면 나중에 누른 쪽이 남습니다.
- **직원은 id 로 참조합니다.** 이름을 바꾸면 기존 기록 · 급여 · 경고 · 평가의 이름이 전부 따라옵니다.
- **직원을 지우면 `ON DELETE CASCADE`** 로 그 직원의 기록 · 커미션 · 급여 · 경고 · 평가가 함께 지워집니다.
- **저장 실패 시** 오른쪽 아래에 빨간 경고와 **다시 시도** 버튼이 뜹니다.
  경고가 떠 있는 동안에는 창을 닫지 마세요 — 그 변경분은 아직 서버에 없습니다.
- **언어 설정은 기기별**입니다. 태블릿은 태국어, PC는 한국어로 따로 둘 수 있습니다.
